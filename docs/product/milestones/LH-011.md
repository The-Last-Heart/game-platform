# LH-011 — Administration Operations Control Center

Day: 4 AM
Depends on: LH-005, LH-006, LH-010
Commit: feat(admin): complete game operations control center

## Product outcome

The administration application becomes a serious bilingual command center. Operators can understand current game health, investigate matches, support players, control safe live behavior, manage access, and verify every sensitive action against real data.

## Design standard

- English is default and full LTR.
- Arabic switches the complete document to RTL and survives reload without flicker.
- Premium charcoal/navy system with disciplined crimson accents.
- Dense but readable information hierarchy.
- Responsive sidebar/navigation, keyboard accessibility, and reliable focus/dialog behavior.
- Real charts/tables with time range, timezone, loading, empty, error, stale, and retry states.
- No generic cheap template, stretched mobile UI, decorative counters, or dead menu.

## Executive dashboard

Show real:

- Active matches excluding completed/halted.
- Players in queue, lobby, play, recovery, spectator, and completed states.
- Matchmaking wait distribution and conversion.
- Challenge success/timeout trends.
- Power grant/use, attacks, shields, and reflections.
- Catalog, mode, localization, and power releases.
- Service readiness/incidents.
- Recent high-risk audit activity.

Every summary links to the relevant filtered records.

## Live Operations

- Live queue/match health filtered by mode, phase, release, app version, locale, and incident.
- Pause/resume new matchmaking.
- Enable/disable bot fill and its threshold.
- Enter/leave maintenance drain.
- Pause challenge from future selection.
- Disable new offensive power activation.
- Halt one genuinely broken match.

Disruptive actions require permission, reason, consequence summary, confirmation, time, and audit. Operators cannot secretly edit hearts, energy, inventory, accepted outcomes, or winners.

## Match Explorer

- Search by match, player, room, and support identifier.
- Six seats and their accepted/ready/resumed/disconnected/bot state.
- Match mode and pinned release identifiers.
- Phase timeline with challenges, submissions, authoritative outcomes, hearts, energy, powers, attacks, elimination, sudden death, and winner.
- Redacted deterministic event timeline suitable for support.
- Clear late/duplicate/reconnect/fallback explanation.
- No token, credential, secret, answer-before-resolution, or private connection exposure.

## Player Support

- Search lightweight player identity and recent matches.
- View eligibility, progression, reconnect history, and support-safe summaries.
- Apply/remove matchmaking suspension with reason, duration, confirmation, permission, and audit.
- Distinguish human, bot, training, and competitive records.
- No chat moderation module because chat does not exist.

## Administrator governance

Complete and preserve:

- super_admin, content_manager, live_ops, translator, viewer.
- Granular permission matrix.
- Search, filter, sort allowlist, pagination, create, profile edit, role/status change, password reset, session listing/revocation, deactivation.
- Self-protection and final-active-super-admin protection.
- Independent sessions, explicit revoke, secure idempotent logout, CSRF/origin protection, and localized errors.

## Audit and system health

- Immutable monotonically ordered audit.
- Actor/action/entity/outcome/time filtering.
- Safely redacted expandable context.
- Security, access, publish, rollback, emergency, suspension, and configuration actions.
- Failed login never attributes the target as actor.
- Service/dependency readiness, releases, migrations/background work, and deployment/config state without secrets.

## Global controls

- Environment-aware versioned settings with owner, description, validation, effective time, and history.
- Real feature controls only.
- Audience and rollout state are explicit.
- Production-critical changes have stronger permission and confirmation.

## Acceptance criteria

- Every navigation item opens a working real-data area.
- Dashboard numbers reconcile with filtered detail pages.
- Active count excludes terminal matches.
- A live incident can be detected, investigated, safely contained, and audited.
- Player suspension affects matchmaking and can be removed safely.
- Match timeline reconstructs the authoritative result.
- Role matrix is enforced server-side and reflected correctly in UI.
- No sensitive value appears in API payload, rendered page, logs, audit, exports, or error detail.
- Every route and interaction works in EN/LTR and AR/RTL.
- Desktop/tablet/mobile browser layouts are usable.
- Admin/backend integration, permission, audit, security, migration, lint, test, and build checks pass.

## Required evidence

- Dashboard-to-detail reconciliation.
- One full incident response recording.
- Match investigation trace.
- Player support suspension lifecycle.
- Role/permission matrix.
- EN/AR browser matrix.
- Commit hash and clean tree.
