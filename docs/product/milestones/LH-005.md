# LH-005 — Pre-match shell

Status: `next`  
Index: [README.md](./README.md)

## Intent

Let a player cold-start the mobile app and reach an existing match join path using reference-faithful pre-match screens — without expanding challenge types or powers.

## Reference screens

| Screen | File | Purpose |
| --- | --- | --- |
| 01 | `01-splash.png` | Launch |
| 02 | `02-onboarding-hearts.png` | Hearts + win condition |
| 03 | `03-home.png` | Home (extend LH-003 home to pack fidelity) |
| 04 | `04-mode-selection.png` | Mode selection |
| 05 | `05-matchmaking.png` | Public queue UI |

## In scope

- Splash → onboarding (first-run) → home
- Mode selection: quick survival vs private room entry points
- Matchmaking UI that joins the existing backend lobby/queue path
- Design tokens, RTL, one primary CTA per screen
- Navigation that does **not** add in-match bottom nav

## Out of scope

- New challenge engines
- Powers / energy unlock UX
- Real economy (currency spend), battle pass, social tabs as product features
- Challenge Studio / translation publishing
- Inventing non-reference flows

## Exit criteria

- Demo: cold start → home → mode → queue or private lobby → existing LH-003 playable path
- Visual review against screens 01–05
- No regression in `simulate:playable` / Flutter tests

## Depends on

LH-003, LH-004A (no hard admin dependency)
