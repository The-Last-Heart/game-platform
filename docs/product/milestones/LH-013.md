# LH-013 — Experience Fidelity, Accessibility, and Release Packaging

Day: 5 AM
Depends on: feature completeness through LH-012
Commit: chore(release): prepare complete rc1 candidate

## Product outcome

The feature-complete game and control center become a coherent, polished, accessible, installable, and deployable RC1 rather than a collection of individually passing features.

## Mobile visual fidelity

Review the full flow against all 30 reference states:

1. Splash.
2. Hearts onboarding.
3. Home.
4. Mode selection.
5. Matchmaking.
6. Private lobby.
7. Ready countdown.
8. Challenge intro.
9 through 21. Challenge preparation and active states.
22. Survived.
23. Lost heart.
24. Power unlocked.
25. Target selection.
26. Incoming danger.
27. Shield.
28. Reflection.
29. Elimination/spectator.
30. Winner/rematch.

Preserve the approved colors, typography, background, spacing, radii, hierarchy, restrained UI-native motion, safe areas, and one-primary-action rule.

Do not replace the reference language with a generic Material UI. Do not add faces, characters, 3D, stock art, or excessive animation.

## Mobile usability matrix

Verify:

- Reference 390 by 844 viewport.
- Small supported phone.
- Tall phone.
- Foldable/narrow and wide portrait behavior where available.
- Android and iOS safe areas.
- Text scaling.
- Keyboard/input on identity and room code.
- App background/foreground.
- Rotation handling according to portrait-first policy.
- Dark rendering, contrast, and outdoor readability.

## Accessibility acceptance

- No color-only gameplay instruction or result.
- Reduced motion across navigation, challenges, heart loss, powers, and winner.
- Motion-ineligible player receives an approved non-motion catalog.
- Audio-ineligible player receives a visual/haptic equivalent.
- Pair fallback works.
- Navigation/setup/result screen-reader labels are meaningful.
- Focus order and dialog focus are correct.
- Touch targets and text bounds remain usable.
- Accessibility profile is private and does not shame or label players.
- A complete match is possible for each supported capability profile.

## Admin fidelity

Verify every route and state in:

- English/LTR.
- Arabic/RTL.
- Desktop.
- Tablet.
- Mobile-width browser.
- Keyboard-only navigation.
- Loading, empty, stale, error, validation, unauthorized, confirmation, success, and destructive-action states.

Charts, tables, filters, sidebars, dialogs, toasts, and dates/numbers must mirror direction correctly without hydration flicker.

## Release configuration

- Separate development, test/staging, and production configuration.
- Validate required environment values and reject unsafe production defaults.
- No secret values committed or archived.
- HTTPS/WSS and allowed-origin expectations documented.
- Migrations and bootstrap process documented.
- Health/readiness and shutdown behavior verified.
- Version identifiers for mobile, backend, admin, contracts, catalogs, rules, powers, and localization are visible to support.
- CI/release commands documented and reproducible.

## Release artifacts

Produce where the environment permits:

- Android release APK for device testing.
- Android AAB ready for signing/submission or signed when authorized material is supplied.
- iOS release archive/build preparation; signed archive only when Apple material and macOS toolchain are available.
- Backend production build/container artifact.
- Admin production build/container artifact.
- Database migration package.
- Environment template with no secrets.
- Release notes, known limitations, rollback steps, and deployment runbook.

Missing signing/cloud/store inputs are listed as external blockers with exact owner/action. They do not turn unfinished application behavior into an accepted RC.

## Real-device/browser journeys

- At least two physical Android devices when available.
- iOS simulator/device where toolchain permits.
- Six concurrent human clients or a documented combination with controlled bots.
- Real Chromium-class browser for admin plus another browser when available.
- Weak/variable network, background/resume, and reconnect.
- Audio, haptic, shake, tilt, multitouch, room-code share, and safe-area behavior.

## Acceptance criteria

- All 30 reference states are either observed in their real product context or explicitly mapped to an approved equivalent.
- No critical visual mismatch, overflow, unreadable state, dead control, fake counter, or untranslated production copy.
- Every supported capability profile can complete a match.
- EN/LTR and AR/RTL admin matrix passes without direction flicker.
- Release artifacts are generated and install/run where the environment supports them.
- Fresh environment setup, migration, bootstrap, backend/admin start, mobile connection, and smoke match are reproducible.
- Dependency/security audits and full formatting/lint/test/build/simulation suite pass.
- Release archive excludes repositories, dependencies, caches, secrets, and irrelevant generated files.

## Required evidence

- Mobile screen matrix mapped to reference 01 through 30.
- Accessibility matrix.
- Admin EN/AR responsive browser matrix.
- Physical device/emulator details.
- Artifact names, sizes, hashes, and install/smoke results.
- External-blocker ledger.
- Commit hash and clean tree.
