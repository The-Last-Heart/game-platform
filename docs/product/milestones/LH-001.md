# LH-001 — Monorepo and Platform Foundation

Status: done (RC1 baseline)
Day: completed before the five-day release window
Commit family: foundation / monorepo / local infra (historical)

## Product outcome

Engineering can develop mobile, backend, admin, and shared contracts in one repository with local PostgreSQL and Redis, documented project rules, and localization boundaries that later milestones must respect.

## Why this remains authoritative

LH-005 through LH-014 assume this foundation already exists. Do not recreate the monorepo, invent a second contracts package, or replace the local Compose topology during the five-day window unless a P0 platform defect forces a surgical fix.

## Delivered baseline

- Apps: Flutter `mobile`, NestJS `backend`, Next.js `admin-web`
- Shared package: `@thelastheart/contracts`
- Local PostgreSQL and Redis via `infra/local` Docker Compose
- Optional Compose profile `apps` for dockerized backend and admin-web
- Admin English/Arabic localization architecture
- Mobile server-managed translation boundary with bootstrap fallback
- Project rules, ADRs, review-archive and secret-safety discipline

## Product rules established here

- Server authority for gameplay state (ADR constraint for later milestones)
- No secrets in git
- Shared contracts are the single typed boundary across clients
- Mobile is Arabic-first; admin is English-first with Arabic/RTL support
- Local infra defaults are development-only and not a production claim

## Out of scope (still excluded)

Anything listed in [RELEASE-BOUNDARY.md](./RELEASE-BOUNDARY.md) as excluded from RC1, including store/IAP, voice recognition, camera challenges, chat, teams, and pay-to-win.

## Acceptance (historical — already satisfied)

- Workspace installs and builds for the three apps and contracts package
- Local Postgres/Redis start and pass health checks
- Foundation docs and ADRs describe structure without authorizing invented gameplay
- Localization boundaries exist without claiming a full publishing product
