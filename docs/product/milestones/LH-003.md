# LH-003 — Playable Mobile Match Slice

Status: done (RC1 baseline)
Day: completed before the five-day release window
Commit family: playable mobile slice (historical)

## Product outcome

An Arabic-first Flutter client can join a realtime match, play the wait-for-state challenge path, lose hearts, spectate, see a winner summary, and recover a session without leaving the reference-pack visual language for the owned screens.

## Why this remains authoritative

LH-005 completes entry and modes around this slice. LH-007–LH-009 add engines and presentation on the same session/reducer/transport stack. Do not discard the playable path or invent a parallel mobile match architecture.

## Reference screens owned (baseline)

`03`, `06`, `07`, `08`, `09`, `10`, `22`, `23`, `29`, `30`

Later milestones own the remaining reference states; LH-013 gates full 01–30 fidelity.

## Delivered baseline

- Private lobby, ready countdown, challenge intro
- Wait-for-state / wait-for-blue engine UI (red wait → cyan go)
- Survive and heart-lost results
- Elimination / spectator and winner summary
- Match session controller, reducer, transport, and session store
- Session recovery hardening
- `pnpm run simulate:playable` regression path
- Portrait-first presentation bound to reference tokens for owned screens

## Product rules established here

- Mobile is Arabic-first and true RTL for shipped player surfaces
- Client never awards hearts, energy, or winners locally against the server
- Loading, reconnecting, and result states are intentional for the playable path
- Reference pack colors, background, and hierarchy constrain UI for owned screens

## Out of scope (historical)

- Full pre-match shell (01–05) as a complete product journey
- Public matchmaking and bot-fill Live Operations controls
- Powers activation loop
- Challenge Studio / translation publishing
- Store, battle pass, chat, or other excluded RC1 surfaces

## Acceptance (historical — already satisfied)

- Vertical playable path against the realtime core works end to end for the wait-for-state engine
- Owned reference screens are represented in product UI, not as disconnected mocks
- Session recovery does not invent a second competitive seat under tested paths
- Playable simulation and relevant mobile/backend regressions remain the baseline gate for later gameplay commits

## Handoff

Extend this slice; do not replace it. LH-005 is the first incomplete RC1 milestone.
