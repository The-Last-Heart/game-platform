# LH-006 — Challenge Studio foundation

Status: `planned`  
Index: [README.md](./README.md)

## Intent

Make challenges **server-driven data**: admin can define/publish templates; mobile/backends consume definitions for a match. Stop growing hardcoded per-challenge Flutter screens.

## In scope

- Admin Challenge Studio MVP: categories + challenge templates CRUD
- Strict contracts for challenge definitions
- Backend storage + publish/immutable versioning model (match pins a definition set)
- Migrate existing wait-for-blue onto the published schema
- Permissioned admin routes; audit sensitive publishes

## Out of scope

- Full challenge pool UI for every reference type (engines come in LH-008/009)
- Translation editor (LH-007)
- Live match intervention
- Voice challenges

## Exit criteria

- Change a wait-for-blue parameter in admin → next match uses it without a client app rebuild
- Contracts + tests cover validation and reject unknown fields
- No divergent handwritten challenge DTOs across apps

## Depends on

LH-004A (admin auth/RBAC), LH-002/LH-003 (match consumption)
